# Возврат в своё лобби — WEB-018

POST с Bearer-токеном и JSON `{gameId}`. ID пользователя берётся только из Auth.
Вызов `get_own_lobby` возвращает актуальный безопасный `GameListItem`.
SQL проверяет открытое лобби, текущего владельца и его существующее участие
под блокировками пользователя и комнаты. Полная/защищённая комната доступна
своему владельцу без проверки пароля и без создания участия.

404 означает, что своё открытое лобби больше недоступно; фронт убирает кнопку.
При сетевой/серверной ошибке кнопка остаётся для повтора. Некорректный DTO
не открывает лобби. Серверные сообщения выводятся через общую обработку ошибок.

Локальная HTTP-проверка (два терминала, дождаться `listening`):

```powershell
postman simulation run postman/simulations/web003.sim.yaml --port 4919 --output ndjson --no-history
deno test --allow-net=127.0.0.1 --allow-env=SUPABASE_URL,SUPABASE_ANON_KEY,SUPABASE_SERVICE_ROLE_KEY --config supabase/functions/get-own-lobby/deno.json supabase/functions/get-own-lobby/supabase-http.test.ts
```

После проверки остановить симуляцию. Это настоящий обработчик/SDK/HTTP против
локального fixture; SQL/RLS и гонки проверяются отдельно через `npm run test:db`.

Для облачного использования сначала применить миграции WEB-018, затем
развернуть актуальные create-game, join-game, game-list и get-own-lobby со
всеми импортами `_shared`. Проверка токена выполняется в обработчике через Auth,
как у остальных функций проекта. Локальная готовность не означает облачный деплой.
