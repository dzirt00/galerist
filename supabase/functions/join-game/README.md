# WEB-003: присоединение к комнате

## Контракт

POST с Bearer-токеном пользователя и JSON:

```json
{"gameId":"22222222-2222-4222-8222-222222222222","password":"необязательный пароль"}
```

ID пользователя берётся только из `auth.getUser(token)`. Поля `userId`,
`p_user_id` и `p_verified_password_hash` из браузерного payload не используются.
Пробелы и UTF-8 в пароле сохраняются. Пустая строка означает отсутствие пароля.

Успех — 200 и безопасный объект `id`, `seat_count`, `occupiedSeatCount`,
`hasPassword`. В SQL членство `(game_id, user_id)` делает повтор идемпотентным:
повтор существующего участника успешен и в полной/защищённой комнате.
Полный GameState, участники других комнат, пароль и хеш в ответ не попадают.

Ошибки возвращаются как `{"error":"понятное сообщение"}` с CORS:

| Статус | Значение |
| --- | --- |
| 400 | Неверный JSON, UUID или тип пароля |
| 401 | Нет действительной пользовательской сессии |
| 403 | Нет подходящего пароля защищённой комнаты |
| 404 | Комната не существует |
| 405 | Метод кроме POST/OPTIONS |
| 409 | Свободных мест нет |
| 500 | Ошибка конфигурации, чтения/записи или формата результата |
| 503 | Не удалось проверить сессию из-за отказа Auth |

Edge Function сверяет PBKDF2-SHA256 через существующий `deriveBits` из
`../create-game/game-password.ts`. В SQL передаётся только проверенный сохранённый
хеш, а не plaintext. SQL блокирует строку комнаты до проверки участника и мест,
сравнивает доказательство с текущим хешем и вставляет участника в одной транзакции.
Право EXECUTE закрыто для PUBLIC/anon/authenticated, оставлено service_role.
Сам SQL не выполняет PBKDF2: подтверждение хеша принимается только от серверной роли.

## Локальная проверка

Из корня репозитория, в первом терминале:

```powershell
postman simulation run postman/simulations/web003.sim.yaml --port 4918 --output ndjson --no-history
```

Во втором, после события `listening`:

```powershell
deno test --config supabase/functions/join-game/deno.json --allow-net=127.0.0.1 --allow-env=SUPABASE_URL,SUPABASE_ANON_KEY,SUPABASE_SERVICE_ROLE_KEY supabase/functions/join-game/supabase-http.test.ts supabase/functions/game-list/supabase-http.test.ts
npm run test:db
npm run verify:web
npm run check:architecture
```

HTTP-тесты используют настоящие обработчики и SDK с локальной Postman simulation;
БД проверяется отдельно в одноразовом PostgreSQL 17 через Docker, включая два
соединения для последнего места и одновременные повторы нового участника.
Компонентные тесты используют mock invoke. Эти проверки не являются облачным E2E.

## Публикация

Облачная публикация не выполнена автоматически. Сначала выполнить SQL **только**
из `supabase/migrations/20261026000000_join_game.sql` в SQL Editor проекта
`mrbrfnxpepogfhmwvdbx` в одной транзакции (BEGIN перед содержимым, COMMIT после).
Миграция рассчитана на первое применение; не запускать её повторно без проверки
существующей функции. Она удаляет старую двухпараметрическую черновую сигнатуру,
если та была установлена, и создаёт трёхпараметрическую с DEFAULT NULL для хеша.

Предыдущие миграции уже применялись через Dashboard без истории CLI:
не выполнять общий `db push` до согласования истории.

Затем из корня репозитория, после входа в Supabase CLI:

```powershell
supabase functions deploy join-game --project-ref mrbrfnxpepogfhmwvdbx --no-verify-jwt
```

CLI соберёт относительный импорт существующего файла create-game/game-password.ts.
Не публиковать только index.ts через Dashboard без его локальных зависимостей.
Функция называется именно `join-game`. Флаг отключает legacy JWT gate платформы;
проверка пользовательского Bearer-токена через getUser остаётся в обработчике.
Используются встроенные SUPABASE_URL/ANON_KEY/SERVICE_ROLE_KEY, в браузер ключ
service_role не добавляется. Изменять create-game для публикации не требуется.

После публикации: войти в локальный Nuxt двумя пользователями, обновить список,
присоединиться к открытой и защищённой комнате; проверить неверный пароль,
повтор и заполненную комнату. Наблюдать подтверждённое лобби и отсутствие
пароля/хеша в ответе. Для сохранения RLS клиентам не выдавать права чтения таблиц
комнат: безопасный список приходит только через game-list.
