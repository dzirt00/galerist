# Проверка миграции и RLS WEB-001

Из корня репозитория: `npm run test:db`. Нужен запущенный Docker с доступом
текущего пользователя к daemon; при первом запуске загружается `postgres:17-alpine`.

Команда создаёт отдельный временный контейнер без открытых портов, подключения
к облачной БД или монтирования файлов. После тестов контейнер и его тома удаляются.
Миграции из `supabase/migrations` выполняются без изменений. Ошибка SQL или
проверки завершает команду с ненулевым кодом.

Проверяются автоматическое создание профиля для двух новых пользователей,
значение `created_at`, включённый RLS, отсутствие анонимного и чужого чтения,
доступ к собственной строке, запрет клиентской вставки и подтверждённый внешний
ключ с `NO ACTION`.

`bootstrap.sql` — тестовое окружение: минимальные `auth.users`, `auth.uid()`
и роли `anon`/`authenticated`. Права на таблицы выдаются обеим ролям специально,
чтобы проверить именно RLS. Это не полная установка Supabase Auth и не миграция
для Dashboard. Тест не проверяет выдачу JWT, PostgREST или настройки прав
облачного проекта. Отправка magic link, возврат, создание профиля новым
пользователем и восстановление сессии дополнительно проверяются вручную.
