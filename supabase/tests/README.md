# Проверка миграций, RLS и создания комнаты WEB-001/002

Из корня репозитория: `npm run test:db`. Нужен запущенный Docker с доступом
текущего пользователя к daemon; при первом запуске загружается `postgres:17-alpine`.

Команда создаёт отдельный временный контейнер без открытых портов, подключения
к облачной БД или монтирования файлов. После тестов контейнер и его тома удаляются.
Миграции из `supabase/migrations` выполняются без изменений. Ошибка SQL или
проверки завершает команду с ненулевым кодом.

Проверяются автоматическое создание профиля для двух новых пользователей,
значение `created_at`, включённый RLS, отсутствие анонимного и чужого чтения,
доступ к собственной строке, запрет клиентской вставки и подтверждённый внешний
ключ с `NO ACTION`.

Для WEB-002 проверяются вызов `create_game` от `service_role`, создание комнаты
на 2/3/4 места и места создателя, сохранение необязательного хеша, повтор
запроса и независимость одинаковых ID запросов у разных пользователей.
Неверная вместимость, отсутствующие ID и неизвестный создатель отклоняются.
Искусственная ошибка последней вставки подтверждает откат комнаты, места и хеша.
Для `anon` и `authenticated` проверены скрытие строк четырёх таблиц через RLS,
запрет прямой вставки комнаты и запрет вызова функции.

Два независимых соединения отправляют один запрос параллельно. Тестовый триггер
задерживает вставку комнаты, чтобы вызвать перекрытие запросов. Проверяются
одинаковые возвращённые ID и ровно один комплект сохранённых записей.
Для этой проверки fixtures фиксируются только во временном контейнере;
затем контейнер удаляется целиком.

`bootstrap.sql` — тестовое окружение: минимальные `auth.users`, `auth.uid()`
и роли `anon`/`authenticated`, а также серверная роль `service_role` с `BYPASSRLS`.
Права на таблицы выдаются клиентским ролям специально,
чтобы проверить именно RLS. Это не полная установка Supabase Auth и не миграция
для Dashboard. Тест не проверяет выдачу JWT, PostgREST или настройки прав
облачного проекта. Отправка magic link, возврат, создание профиля новым
пользователем и восстановление сессии дополнительно проверяются вручную.
Хеши в тестах — условные строки: проверка длины пароля, настоящее хеширование,
проверка токена, безопасный DTO и сценарий браузера WEB-002 пока не проверяются.
