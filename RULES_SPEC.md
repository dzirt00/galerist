# Реестр правил проекта «Галерист»

> Статус документа: черновая формализация источника. Правило считается согласованным только после смены статуса `draft` на `approved`.

## 1. Назначение и границы

Этот файл содержит проверяемые контракты игрового движка. Он не воспроизводит текст или оформление исходного руководства. Формулировки ниже являются кратким техническим пересказом механик.

Источником служит русское руководство к настольной игре, разделы «Подготовка к игре» — «Финальный подсчёт» и «Одиночная игра». Номера страниц указаны по печатной нумерации источника.

В продуктовый MVP входят партии на 2–4 места, занятые людьми или ботами. Официальный одиночный вариант с нейтральным соперником вынесен в отдельный отложенный раздел и не должен смешиваться с режимом «один человек против ботов».

## 2. Статусы и трассировка

Каждая запись содержит:

- `spec`: `draft`, `needs_decision`, `approved` или `deferred`;
- `implementation`: `no`, `partial` или `yes`;
- `tests`: `no`, `partial` или `yes`.

После появления реализации в поле статуса добавляется ссылка на модуль, а после появления тестов — имя теста или сценария. Значение `partial` означает, что существующий код совпадает лишь с частью контракта и ещё не реализует правило целиком.

События перечислены как предполагаемые доменные имена. Они не фиксируют TypeScript API до отдельного согласования модели `GameEvent`.

## 3. Нерешённые вопросы и необходимые ADR

| ID | Статус | Решение или оставшийся вопрос |
| --- | --- | --- |
| ADR-001 | `needs_decision` | Случайный выбор подтверждён; нужно решить, обязан ли одинаковый seed воспроизводить первого игрока и всю случайную подготовку |
| ADR-002 | `behavior_approved` | Подтверждена последовательность: обычная игра до двух из трёх триггеров → конец текущего круга → финальный круг → подсчёт → итоговая таблица; остаётся выбрать представление фаз в типах |
| ADR-003 | `behavior_approved` | Обычный ход состоит из упорядоченных частей; выдворение подтверждено как специальное дополнительное действие после хода активного игрока, а не как новый обычный ход; остаётся выбрать формат команд и состояния черновика |
| ADR-004 | `approved` | Порядок элементов `players` является фиксированным порядком мест по часовой стрелке |
| ADR-005 | `needs_decision` | Какие исходные названия допустимы во внутренней модели и какие нейтральные названия увидит пользователь |
| ADR-006 | `needs_data` | Формат и источник справочных данных компонентов: карты целей, награды клеток, шкалы, жетоны и произведения |

## 4. Общие инварианты

### CORE-001 — Число участников MVP

- **Источник / фаза / триггер:** границы продукта и подготовка, с. 2; создание партии.
- **Условия:** обычная онлайн-партия содержит 2, 3 или 4 места.
- **Эффект:** конфигурация и список игроков содержат одинаковое допустимое число участников.
- **Исключения:** официальный одиночный вариант не является партией с одним обычным местом.
- **События:** `GameCreated` после успешной полной подготовки.
- **Проверки:** принять 2/3/4 места; отклонить другое число и несовпадение конфигурации со списком.
- **Статус:** `spec: approved` · `implementation: yes` · `tests: yes`.

### CORE-002 — Ограниченность компонентов

- **Источник / фаза / триггер:** подготовка, с. 2; любая попытка получить компонент.
- **Условия:** монеты не ограничены; остальные физические компоненты ограничены текущим запасом.
- **Эффект:** доступный компонент перемещается из соответствующего запаса.
- **Исключения:** если компонент закончился, игрок его не получает; специальные правила билетов описаны в `TICKET-002`.
- **События:** событие получения создаётся только для фактически полученного количества.
- **Проверки:** получение из непустого запаса; пустой запас не создаёт компонент и не уводит количество ниже нуля.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### CORE-003 — Цель и победитель

- **Источник / фаза / триггер:** обзор, с. 4; завершение финального подсчёта.
- **Условия:** все этапы финального подсчёта выполнены.
- **Эффект:** победителем становится участник с наибольшим итоговым количеством монет; ничьи разрешаются по `SCORE-007`.
- **Исключения:** победителей может быть несколько, если все критерии ничьей равны.
- **События:** `WinnerDetermined`.
- **Проверки:** единственный лидер; полная ничья после всех дополнительных критериев.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### CORE-004 — Неизменяемые переходы движка

- **Источник / фаза / триггер:** технический принцип проекта; любой переход состояния.
- **Условия:** движок получает снимок `GameState`.
- **Эффект:** успешный переход возвращает новый неизменяемый корневой объект, а отклонённый вызов не меняет входной снимок.
- **Исключения:** ссылки на неизменённые вложенные данные могут сохраняться, если контракт перехода это разрешает.
- **События:** отсутствуют при отклонении.
- **Проверки:** сравнить вход с глубокой копией после успешного и отклонённого вызова; проверить заморозку результата.
- **Статус:** `spec: approved` · `implementation: partial` · `tests: partial`.

## 5. Подготовка обычной партии

### SETUP-001 — Пулы посетителей и билетов

- **Источник / фаза / триггер:** подготовка, с. 2; создание партии.
- **Условия:** известное число игроков.
- **Эффект:** при 4 игроках используется полный пул посетителей и по 20 билетов каждого цвета; при 3 удаляются по 2 посетителя каждого типа и используется по 15 билетов; при 2 удаляются по 4 посетителя каждого типа и используется по 10 билетов.
- **Исключения:** удалённые компоненты недоступны до конца партии.
- **События:** `VisitorBagPrepared`, `TicketOfficePrepared`.
- **Проверки:** точные количества для 2/3/4 игроков; отсутствие удалённых компонентов в доступном запасе.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### SETUP-002 — Начальные влияние и монеты

- **Источник / фаза / триггер:** подготовка, с. 2–3; создание партии.
- **Условия:** места игроков созданы.
- **Эффект:** каждый игрок начинает с 10 влияния и 10 монет.
- **Исключения:** нет.
- **События:** начальные значения входят в `GameCreated`.
- **Проверки:** все участники получают одинаковые значения; входные объекты игроков не изменяются.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### SETUP-003 — Заказы

- **Источник / фаза / триггер:** подготовка, с. 2; создание партии.
- **Условия:** доступен полный набор карт заказов.
- **Эффект:** колода перемешивается seed-детерминированно; четыре верхние карты образуют открытую область заказов.
- **Исключения:** нет.
- **События:** `OrderMarketPrepared`.
- **Проверки:** одинаковый seed даёт одинаковый порядок; область содержит четыре карты, исключённые из закрытой колоды.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### SETUP-004 — Выбор художников

- **Источник / фаза / триггер:** подготовка, с. 2; создание партии.
- **Условия:** 16 художников распределены по четырём жанрам и двум категориям.
- **Эффект:** seed-детерминированный отбор заполняет восемь уникальных клеток так, чтобы каждый жанр был представлен одним художником каждой категории; первый выбранный художник синей категории открыт и получает начальную известность, остальные закрыты.
- **Исключения:** художник, чья клетка уже занята, исключается из текущей партии.
- **События:** `ArtistsPrepared`, `ArtistOpened` для начального художника.
- **Проверки:** восемь уникальных клеток и требуемое распределение; одинаковый seed воспроизводит выбор.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### SETUP-005 — Бонусы, коллекционеры и подписи художников

- **Источник / фаза / триггер:** подготовка, с. 2; после `SETUP-004`.
- **Условия:** художники выбраны.
- **Эффект:** на каждого закрытого художника кладётся случайный бонус; на каждого красного художника — один коллекционер из мешочка; рядом с каждым художником размещаются два его жетона подписи.
- **Исключения:** начальный открытый художник бонус не получает; неиспользованные бонусы удаляются из партии.
- **События:** входят в `ArtistsPrepared`.
- **Проверки:** бонус отсутствует только у начального открытого художника; количество подписей каждого художника равно двум.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### SETUP-006 — Стопки произведений и посетители на рынке

- **Источник / фаза / триггер:** подготовка, с. 2; создание партии.
- **Условия:** известны четыре жанра произведений.
- **Эффект:** стопка каждого жанра перемешивается отдельно; верхняя работа временно откладывается; на новую верхнюю работу помещается случайное число посетителей, равное напечатанному числу билетов независимо от их цветов.
- **Исключения:** отложенные работы далее используются для выдающихся произведений по `SETUP-009`.
- **События:** `ArtworkMarketPrepared`.
- **Проверки:** четыре независимые стопки; число посетителей на каждой верхней работе совпадает с её значением.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### SETUP-007 — Реклама

- **Источник / фаза / триггер:** подготовка, с. 2; создание партии.
- **Условия:** доступны жетоны рекламы всех уровней.
- **Эффект:** жетоны группируются на предназначенных для уровней клетках.
- **Исключения:** количество жетонов ограничено.
- **События:** `PromotionSupplyPrepared`.
- **Проверки:** каждый жетон находится в стопке своего уровня; общий запас сохраняется.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### SETUP-008 — Международный рынок

- **Источник / фаза / триггер:** подготовка, с. 2–3; создание партии.
- **Условия:** доступен пул жетонов репутации.
- **Эффект:** при 3–4 игроках 12 случайных жетонов заполняют верхние четыре ряда трёх колонок; при 2 игроках восемь жетонов заполняют только первую и третью колонки. Дополнительно по одному из четырёх случайных жетонов размещается у каждой локации.
- **Исключения:** средняя колонка в партии на двоих не используется; остальные жетоны не участвуют в этих ячейках.
- **События:** `InternationalMarketPrepared`, `LocationReputationPrepared`.
- **Проверки:** раскладки для 2/3/4 игроков; уникальность выбранных жетонов; средняя колонка пуста при двух игроках.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### SETUP-009 — Выдающиеся произведения

- **Источник / фаза / триггер:** подготовка, с. 3; после `SETUP-006`.
- **Условия:** отложено по одной работе каждого жанра.
- **Эффект:** отложенные работы перемешиваются; на мольберты помещаются 3 работы при 4 игроках, 2 при 3 игроках и 1 при 2 игроках.
- **Исключения:** неиспользованные работы и мольберты удаляются из партии.
- **События:** `MasterpieceAuctionPrepared`.
- **Проверки:** количество соответствует числу игроков; выставленные работы уникальны и выбраны из четырёх отложенных.
- **Статус:** `spec: needs_decision` · `implementation: no` · `tests: no` — OCR-фрагмент шага требует сверки с оригинальной страницей.

### SETUP-010 — Начальные посетители поля

- **Источник / фаза / триггер:** подготовка, с. 3; создание партии.
- **Условия:** мешочек подготовлен.
- **Эффект:** четыре случайных посетителя помещаются на площадь и по одному случайному посетителю — в вестибюль каждого участника.
- **Исключения:** выбранные посетители удаляются из мешочка.
- **События:** `InitialVisitorsPlaced`.
- **Проверки:** площадь содержит четыре, каждый вестибюль один; суммарное число посетителей сохраняется.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### SETUP-011 — Первый игрок и круговой порядок

- **Источник / фаза / триггер:** подготовка, с. 3; создание партии.
- **Условия:** участники размещены в круговом порядке.
- **Эффект:** первый игрок выбирается случайно и воспроизводимо через seed; обычная партия начинается с его хода и продолжается по часовой стрелке.
- **Исключения:** конкретное представление порядка ожидает ADR-001 и ADR-004.
- **События:** `FirstPlayerSelected`.
- **Проверки:** одинаковый seed даёт одинакового первого игрока; каждый допустимый ID может быть выбран набором seed.
- **Статус:** `spec: needs_decision` · `implementation: partial` · `tests: partial` — сейчас первым всегда становится `players[0]`.

### SETUP-012 — Планшет и стартовая локация игрока

- **Источник / фаза / триггер:** подготовка, с. 3; после выбора первого игрока.
- **Условия:** для каждого игрока доступны 10 помощников, планшет, галерист и карты целей.
- **Эффект:** восемь помощников заполняют очередь безработных, два занимают любые рабочие места офиса; в обратном порядке хода игрок выбирает стартовую локацию, размещает там галериста, забирает жетон репутации локации на третью перегородку; каждый тайно получает по карте куратора и арт-дилера.
- **Исключения:** оставшиеся у локаций жетоны репутации удаляются после выбора всех игроков.
- **События:** `PlayerBoardPrepared`, `StartingLocationChosen`, `PrivateGoalsDealt`.
- **Проверки:** обратный порядок выбора; по 10 помощников; заняты две офисные клетки; цели видимы только владельцу/серверу.
- **Статус:** `spec: needs_decision` · `implementation: no` · `tests: no` — нужны справочные данные планшета и серверная модель скрытой информации.

## 6. Раунды, ход и передача инициативы

### TURN-001 — Начало обычной партии

- **Источник / фаза / триггер:** процесс игры, с. 5; завершение подготовки.
- **Условия:** подготовка полностью завершена и первый игрок определён.
- **Эффект:** начинается первый раунд, активным становится первый игрок.
- **Исключения:** запуск неполной или уже начатой партии запрещён.
- **События:** `GameStarted`, `RoundStarted`, `TurnStarted`.
- **Проверки:** корректное начало; отклонение повторного запуска без изменения состояния.
- **Статус:** `spec: draft` · `implementation: partial` · `tests: partial`.

### TURN-002 — Состав обычного хода

- **Источник / фаза / триггер:** процесс игры и действия управления, с. 5; начало хода.
- **Условия:** ход принадлежит активному игроку.
- **Эффект:** игрок обязательно перемещает галериста и выполняет одно действие новой локации; дополнительно он может выполнить не более одного действия управления до либо после действия локации.
- **Исключения:** действие управления необязательно; порядок фиксируется выбранной последовательностью действий.
- **События:** `TurnDraftConfirmed` с упорядоченным набором событий отдельных действий.
- **Проверки:** варианты управление→локация, локация→управление и только локация; отклонить два действия управления или отсутствие действия локации.
- **Статус:** `spec: needs_decision` · `implementation: no` · `tests: no` — ожидает ADR-003.

### TURN-003 — Перемещение галериста

- **Источник / фаза / триггер:** действия локаций, с. 5; обязательное перемещение хода.
- **Условия:** если галерист находится в локации, он обязан перейти в другую локацию; если находится дома в галерее, может выбрать любую локацию.
- **Эффект:** галерист занимает выбранную локацию и открывает одно из двух её действий.
- **Исключения:** остаться в прежней локации нельзя.
- **События:** `GalleristMoved`.
- **Проверки:** переход между разными локациями; отклонение прежней локации; выход из домашней галереи в любую локацию.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### TURN-004 — Оставление помощника

- **Источник / фаза / триггер:** действия локаций, с. 5; перемещение между двумя локациями.
- **Условия:** у игрока есть помощник в офисе или другой локации.
- **Эффект:** перед уходом игрок может оставить ровно одного своего помощника в покидаемой локации, переместив его из допустимого источника.
- **Исключения:** при отсутствии доступного помощника эффект недоступен; помощник не обязателен.
- **События:** `AssistantLeftAtLocation`.
- **Проверки:** помощник из офиса и другой локации; отсутствие помощника; попытка оставить больше одного.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### TURN-005 — Разрешение последствий и следующий игрок

- **Источник / фаза / триггер:** процесс игры, с. 5–6; окончание действий активного игрока.
- **Условия:** действие локации и выбранное действие управления завершены.
- **Эффект:** сначала разрешаются специальные дополнительные действия выдворения и отложенные эффекты конца хода, затем ход переходит следующему участнику по кругу; выдворенный игрок не получает новый обычный ход.
- **Исключения:** в дополнительном финальном раунде действия выдворения подавлены по `END-004`.
- **События:** `TurnEnded`, затем возможные события выдворения и `TurnStarted`.
- **Проверки:** выдворение не меняет круговой порядок; передача хода происходит после всех отложенных эффектов.

- **Эффект:** коллекционер входит в галерею только при наличии свободного места.

- **События:** обычное событие покупки только при исключении.
- **Проверки:** обычная покупка отклонена; контрактная разрешена.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

## 15. Финальный подсчёт

### SCORE-001 — Порядок этапов

- **Источник / фаза / триггер:** финальный подсчёт, с. 15; `FinalScoringStarted`.
- **Условия:** дополнительный финальный раунд завершён.
- **Эффект:** последовательно считаются лидерство рынка, жетоны репутации, выставка, аукцион, карты куратора, карты арт-дилера, влияние, затем определяется победитель.
- **Исключения:** стартовый жетон репутации, оставшийся на третьей перегородке, перед подсчётом удаляется.
- **События:** событие каждого этапа и `FinalScoringCompleted`.
- **Проверки:** фиксированный порядок; повторный запуск не начисляет награды дважды.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### SCORE-002 — Лидерство на международном рынке

- **Источник / фаза / триггер:** финальный подсчёт, с. 15; первый этап.
- **Условия:** по каждой используемой колонке считаются все помощники игрока в верхней и нижней частях.
- **Эффект:** места получают напечатанные для колонки суммы; при ничьей суммы спорных мест складываются и делятся поровну с округлением вниз; игрок без помощников награду не получает.
- **Исключения:** каждая колонка считается независимо; отключённая колонка партии на двоих пропускается.
- **События:** `MarketLeadershipScored`.
- **Проверки:** явные 1/2/3 места; ничья за разные диапазоны мест; ноль помощников.
- **Статус:** `spec: needs_decision` · `implementation: no` · `tests: no` — нужна таблица наград всех колонок.

### SCORE-003 — Жетоны репутации и выставка

- **Источник / фаза / триггер:** финальный подсчёт, с. 15 и справочник с. 20.
- **Условия:** репутационные жетоны находятся на планшетах, работы — в выставочных залах.
- **Эффект:** каждый жетон применяет собственную формулу влияния/монет; затем каждая выставленная работа приносит текущую цену продажи.
- **Исключения:** жетон конвертации влияния в монеты считается первым, если это предписано его текстом.
- **События:** `ReputationTokensScored`, `ExhibitionScored`.
- **Проверки:** каждый тип жетона отдельным параметризованным сценарием; несколько работ разных художников.
- **Статус:** `spec: needs_decision` · `implementation: no` · `tests: no` — формулы должны стать отдельным набором справочных данных.

### SCORE-004 — Аукцион выдающихся произведений

- **Источник / фаза / триггер:** финальный подсчёт, с. 15; этап аукциона.
- **Условия:** ставка игрока равна сумме значений рядов его помощников в нижней части рынка: 1, 3 или 6 за помощника.
- **Эффект:** игроки по убыванию ставки выбирают по одной доступной выдающейся работе, пока работы не закончатся; работа прикладывается к одной карте цели и может помогать её выполнению; игрок немедленно получает её цену как цену работы самого известного открытого художника того же жанра.
- **Исключения:** один игрок получает не более одной работы; ничья разрешается большей ставкой в колонке 3, затем 2, затем 1.
- **События:** `AuctionResolved`, `ExceptionalArtworkAwarded`, `CoinsReceived`.
- **Проверки:** разные ставки; все уровни разрешения ничьей; игроков больше, чем работ; ограничение одной работы.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

### SCORE-005 — Карты целей

- **Источник / фаза / триггер:** финальный подсчёт, с. 15; после аукциона.
- **Условия:** известны приобретённые, выставленные, проданные и полученные на аукционе работы.
- **Эффект:** карта куратора начисляет монеты за указанные коллекции выставленных работ и не более одной аукционной работы; одна работа может входить в несколько целей. Карта арт-дилера начисляет монеты за указанные наборы проданных работ.
- **Исключения:** конкретные цели и суммы задаются данными карт.
- **События:** `CuratorCardScored`, `DealerCardScored`.
- **Проверки:** каждая карта и цель; одна работа в нескольких целях; ограничения аукционной работы.
- **Статус:** `spec: needs_decision` · `implementation: no` · `tests: no` — отсутствуют проверенные данные карт.

### SCORE-006 — Финальная ценность влияния

- **Источник / фаза / триггер:** финальный подсчёт, с. 15; после карт целей.
- **Условия:** известна итоговая позиция на шкале влияния.
- **Эффект:** игрок получает указанное шкалой число монет.
- **Исключения:** значения символов монет, используемые во время игры, не определяют эту сумму напрямую.
- **События:** `InfluenceScored`.
- **Проверки:** границы каждого диапазона шкалы.
- **Статус:** `spec: needs_decision` · `implementation: no` · `tests: no` — нужна точная таблица шкалы.

### SCORE-007 — Разрешение ничьей

- **Источник / фаза / триггер:** финальный подсчёт, с. 15; несколько лидеров по монетам.
- **Условия:** рассматриваются только претенденты с максимальным числом монет.
- **Эффект:** последовательно сравниваются: число всех приобретённых работ; число посетителей в галерее; число помощников в игре, исключая безработных и удалённых.
- **Исключения:** если равенство сохраняется, все оставшиеся претенденты побеждают.
- **События:** `WinnerDetermined`.
- **Проверки:** ничья разрешается на каждом критерии; полное равенство даёт нескольких победителей.
- **Статус:** `spec: draft` · `implementation: no` · `tests: no`.

## 16. Официальный одиночный вариант — вне MVP

### SOLO-001 — Область применения

- **Источник / фаза / триггер:** одиночная игра, с. 16; создание официальной одиночной партии.
- **Условия:** один человек играет против нейтрального автоматизированного соперника источника.
- **Эффект:** применяются обычные правила с изменениями этого раздела.
- **Исключения:** режим не равен обычной партии с ботом и не входит в текущий MVP.
- **События:** не проектируются до включения режима в scope.
- **Проверки:** отсутствуют до отдельного решения продукта.
- **Статус:** `spec: deferred` · `implementation: no` · `tests: no`.

### SOLO-002 — Подготовка и движение нейтрального соперника

- **Источник / фаза / триггер:** одиночная игра, с. 16; подготовка и конец каждого хода человека.
- **Условия:** используется отдельный цвет нейтрального соперника, 10 билетов каждого цвета, только первая и третья колонки рынка и уменьшенный пул посетителей.
- **Эффект:** после первого хода человека нейтральный галерист ставится в противоположную локацию; затем каждый раз движется по часовой стрелке и оставляет помощника.
- **Исключения:** нейтральный соперник не выполняет локационные и управляющие действия, кроме специального размещения на рынке.
- **События:** `SoloOpponentPlaced`, `SoloOpponentMoved`, `SoloAssistantLeft` — имена предварительные.
- **Проверки:** первое размещение напротив; последующее круговое движение; нейтральный соперник не выполняет обычное действие локации.
- **Статус:** `spec: deferred` · `implementation: no` · `tests: no`.

### SOLO-003 — Выдворение и рынок нейтрального соперника

- **Источник / фаза / триггер:** одиночная игра, с. 16; выдворение или вход нейтрального соперника на рынок.
- **Условия:** применяется специальный порядок помощников.
- **Эффект:** при выдворении его фишки сбрасывается билет из крупнейшей стопки; помощники рынка ставятся в первую свободную ячейку сверху слева, чередуя верхнюю и нижнюю части, с переходом в незаполненную часть; репутация занятой ячейки сбрасывается.
- **Исключения:** движение нейтрального галериста нельзя изменить выдворением.
- **События:** `SoloTicketDiscarded`, `SoloMarketAssistantPlaced`, возможное `ReputationTokenDiscarded`.
- **Проверки:** выдворение каждого типа фишки; чередование частей рынка; переход в незаполненную часть.
- **Статус:** `spec: deferred` · `implementation: no` · `tests: no`.

### SOLO-004 — Окончание и цели

- **Источник / фаза / триггер:** одиночная игра, с. 16; касса полностью без билетов.
- **Условия:** доигрывается текущий раунд.
- **Эффект:** человек выполняет ещё одно действие в другой локации без последующего движения нейтрального соперника; результат оценивается по выбранному уровню набора целей и порогов.
- **Исключения:** выдворение нейтральной фишки на рынке всё ещё размещает его помощника.
- **События:** `SoloEndTriggered`, `SoloFinalActionStarted`, `SoloResultEvaluated`.
- **Проверки:** конец раунда и одно дополнительное действие; отсутствие движения нейтрального соперника; каждый уровень целей как отдельный сценарий.
- **Статус:** `spec: deferred` · `implementation: no` · `tests: no`.

## 19. Порядок согласования и реализации

1. Закрыть `ADR-001`–`ADR-004` и получить данные `DATA-001`, `DATA-002`, `DATA-006`.
2. Согласовать и реализовать `SETUP-*` вместе с детерминированными тестами для 2/3/4 игроков.
3. Согласовать модель составного хода `TURN-*`, затем `MGMT-*` и `EJECT-*`.
4. Последовательно реализовать действия локаций: художники, продажи, медиацентр, международный рынок.
5. Реализовать ресурсы, промежуточный подсчёт и известность.
6. Реализовать `END-*` и только затем `SCORE-*`.
7. Официальный одиночный вариант не начинать без отдельного изменения продуктового scope.

Для каждого правила порядок работы одинаков: согласовать `draft`, добавить падающий положительный тест, реализовать минимальное поведение, добавить граничный тест, выполнить проверки пакета и обновить статусы со ссылками на тесты.
