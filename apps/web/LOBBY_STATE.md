# Состояния и действия лобби

Карта `app/GameLobby.vue` после упорядочивания от 2026-11-17. Сервер остаётся владельцем состава, прав и допустимости команд; локальные флаги управляют ожиданием и отображением.

## Состояния

| Переменная | Начальное значение | Кто меняет и зачем | Ошибка и повтор |
| --- | --- | --- | --- |
| `isCommandPending` | `false` | `isReady`, `leaveGame`, `addBot`, `editChangeSeatCount` включают перед командой; `finishCommand` выключает в `finally` | Снимается при любом результате; блокирует параллельные действия |
| `isRefreshGame` | `false` | Только `refreshGame`: включает перед чтением и выключает в `finally` | После ошибки можно повторить чтение |
| `refreshPending` | `false` | `refreshGame` ставит при занятости; `addBot` — после подтверждённого успеха. Начало чтения и подтверждённый выход сбрасывают | Сигнал во время неуспешной команды всё равно приводит к чтению после её завершения. Несколько сигналов объединяются |
| `active` | `true` | `onUnmounted` устанавливает `false` | Не отменяет серверный запрос; проверки после ожидания запрещают применять поздний ответ и запускать отложенное чтение |
| `pendingBotRequest` | `null` | `addBot` создаёт `{gameId, requestId}` перед первой отправкой и очищает после проверенного успеха | Сохраняется при ошибке для повтора с тем же ID; обычная переменная, поскольку отображение от неё не зависит |
| `pendingLeaveGameRequest` | `null` | `leaveGame` создаёт запрос перед отправкой и очищает после проверенного успеха | Сохраняется для повтора, в том числе после отказа чтения состава; `ref`, поскольку участвует в доступности выхода |
| `playerList` | `null` | Чтение очищает старый состав и сохраняет проверенный состав с текущим человеком | При неуспешном чтении состав неизвестен |
| `creatorId` | `null` | Чтение очищает значение, затем устанавливает подтверждённый ID создателя | Без подтверждения управление скрыто |
| `playerIsReady` | `null` | Чтение своего места и подтверждённая команда готовности | Не изображает успех команды при ошибке; отсутствие своего места сбрасывает значение |
| `changeSeatCount`, `turnDurationMinutes` | Настройки из входной комнаты либо `null` | Локальные черновики, изменяемые пользователем | Фоновое чтение обновляет сохранённые настройки родителя, сохраняя черновики |
| `message` | Пустая строка | Обработчики и статус Realtime | Серверный текст проходит через `getFunctionErrorMessage` и выводится текстом |

`isBusy = isCommandPending || isRefreshGame`. Отдельный `isChangeSeatCount` удалён: он всегда включался вместе с флагом команды и не добавлял самостоятельного состояния. Команды завершают только собственное ожидание через `finishCommand`; флаг чтения меняет само чтение.

## Действия и ограничения

| Действие | Условие / владелец эффекта | Подтверждённый результат |
| --- | --- | --- |
| `isReady` | Кнопка и обработчик используют `isReadyDisabled`: нет комнаты либо занят. Сервер проверяет команду `ready-to-game` | Обновляет собственную готовность из проверенного ответа |
| `refreshGame` | Нет комнаты или компонент закрыт — выход. Занят — сохранить `refreshPending`, не отправлять параллельное чтение | `get-game-players` обновляет состав, создателя и события настроек/занятости |
| `leaveGame` | Кнопка и обработчик используют `isLeaveDisabled`. Нужны комната, отсутствие занятости и либо сохранённый запрос, либо подтверждённая роль обычного участника | `leave-game` → очистка запроса и очереди → `leaveRoom` |
| `addBot` | Комната есть; `areSettingsDisabled` выключен: нет занятости и есть подтверждённое право управления | `add-bot` → очистка запроса → очередь чтения состава |
| `editChangeSeatCount` | Существующие валидаторы вместимости и минут; комната есть; тот же `areSettingsDisabled`, что у формы | `change-settings-game` → `changeData` с обеими проверенными настройками |

Валидация формы и прежние сообщения остаются в обработчике. Форма отправляется через `submit.prevent`; `novalidate` позволяет общей JS-валидации показать прежнее сообщение, включая отсутствие выбора. Добавление бота находится за пределами формы и не отправляет настройки.

## Потребители и сохраняемые сценарии

- `app.vue` принимает `changeData`, обновляет настройки `createdGame`; принимает `occupiedSeatCountChange`, обновляет занятость; принимает `leaveRoom`, возвращает список комнат. Контракты событий сохранены.
- Публичный `GamePlayer` используется валидатором состава в `app/utils/lobby-validation.ts`; его поля сохранены. Серверные DTO и Edge Functions не меняются.
- Realtime вызывает существующий `refreshGame`, а не применяет данные сигнала. Ключ комнаты в `app.vue` обеспечивает отдельный экземпляр компонента при переходе между комнатами.
- Шаблон разделён на сведения о комнате, действия участника с составом и управление создателя. Подписи и порядок кнопок сохранены.
- Существующие тесты готовности, состава, настроек, прав управления, добавления бота, выхода, ошибок и Realtime проверяют эти пользовательские сценарии. Обязательная общая проверка интерфейса: `npm run verify:web`.

Пример очереди: `addBot` включает `isCommandPending` → сигнал вызывает `refreshGame` → занятому чтению ставится `refreshPending` → команда завершается → `finishCommand` снимает занятость → при `active && refreshPending` начинается чтение. Ошибка команды не отменяет уже полученный сигнал. После размонтирования отложенное чтение не запускается.
