# Словарь предметной области

Этот файл задаёт единый язык для имён в коде «Галериста». Правила и числовые данные по-прежнему определяет `RULES_SPEC.md`; этот словарь определяет, **как называть** уже согласованные понятия в типах, функциях, полях, событиях и тестах.

## Правила использования

- Идентификаторы в коде писать на английском; описания тестов и комментарии могут быть на русском.
- Для одного понятия использовать одно каноническое имя из этого файла. Не вводить сокращение или синоним только ради краткости.
- Перед добавлением публичного типа, поля или функции искать термин здесь и в существующем коде.
- Если нового термина здесь нет, но его смысл однозначен, добавить его в словарь в том же изменении. Если смысл влияет на игровое правило, сначала согласовать его и не угадывать `needs_decision`/`needs_data`.
- Не переименовывать несвязанный старый код попутно. Наследованное имя исправлять отдельным ограниченным изменением либо при работе с соответствующим вертикальным срезом.
- Техническое имя проекта и npm-пространство остаются `galerist`. Участник партии называется `player`; отдельный тип `Gallerist` без реальной необходимости не вводить.

## Участники, компоненты и ресурсы

| Каноническое имя | Значение |
| --- | --- |
| `player` | Участник партии: человек или бот. |
| `artist` | Художник, связанный с жанром, категорией и известностью. |
| `artwork` | Обычное произведение искусства. |
| `masterpiece` | Выдающееся произведение для финального аукциона; не синоним `artwork`. |
| `visitor` | Посетитель любого типа. Конкретные множества: `investors`, `celebrities`, `collectors`. |
| `assistant` | Помощник игрока. |
| `order` | Карта заказа/контракта отдела продаж. Не использовать расплывчатое `card`, если имеется в виду заказ. |
| `curatorGoal` | Карта цели куратора. |
| `dealerGoal` | Карта цели арт-дилера. |
| `goalCard` | Общий термин только там, где код действительно работает с обоими типами целей. |
| `goalCardDefinition` / `GoalCardDefinition` | Полное неизменяемое описание карты личной цели. |
| `goalRewardTier` / `GoalRewardTier` | Один набор требуемых жанров (`requiredGenres`) и соответствующая награда в монетах. |
| `ticket` | Билет посетителя определённого цвета. |
| `ticketsByColor` | Запас билетов конкретного игрока по цветам. |
| `requestedColors` | Конкретные цвета, выбранные для одного эффекта получения билетов. |
| `replacementColorsByRequestedColor` | Выбранный цвет билета кассы для обмена по каждому недоступному требуемому цвету. |
| `coin` / `coins` | Денежный ресурс игрока. |
| `influence` | Влияние игрока на шкале 0–35; расходуемый ресурс. |
| `fame` | Известность художника, определяющая цену его работ. Не влияние игрока. |
| `reputationToken` | Жетон репутации на международном рынке или перегородке планшета. Не числовой ресурс игрока. |
| `promotion` | Реклама: действие, уровень или жетон рекламы в зависимости от уточняющего суффикса (`promotionLevel`, `promotionToken`). |
| `bonus` | Разовая награда/эффект компонента; конкретный источник указывать в имени. |
| `reward` | Результат выполнения условия или действия. |
| `signatureToken` | Подпись художника, размещаемая на произведении. |
| `bid` | Ставка игрока на международном рынке или аукционе. |
| `easel` | Место произведения на рынке художников. |
| `winnerIds` | победители в партии |

### Критические различия

- `influence` принадлежит игроку и может расходоваться; `fame` принадлежит художнику и задаёт стоимость; `reputationToken` — физический жетон/позиция рынка.
- `promotion` не является синонимом `fame`: реклама может увеличить известность, но это разные понятия.
- `order` — контракт отдела продаж, а `turnOrder` — порядок хода. Для второго всегда писать составное имя.
- `artwork` — общее произведение, `masterpiece` — отдельный компонент финального аукциона.
- `collector` — тип посетителя, `curatorGoal` — тип личной цели. Эти слова не взаимозаменяемы.

Для коллекций использовать смысловые уточнения:

- `visible…` — открыто всем;
- `remaining…` — скрытый остаток после подготовки или расхода;
- `available…` — сейчас разрешено выбрать;
- `selected…` — уже выбрано;
- `deferred…` — намеренно отложено для следующего этапа.

## Действия и глаголы

| Префикс | Когда использовать |
| --- | --- |
| `create…` | Создать новую доменную сущность или корневое состояние. |
| `prepare…` | Детерминированно подготовить часть setup из каталога и RNG. |
| `calculate…` | Чисто вычислить числовое значение без изменения состояния. |
| `determine…` | Чисто определить победителя, порядок или иной дискретный результат. |
| `apply…` | Применить уже определённый эффект и вернуть новую неизменяемую структуру. |
| `choose…` | Зафиксировать решение игрока после проверки допустимости. |
| `start…` | Начать фазу или процесс. |
| `advance…` | Перевести существующий процесс на следующий этап. |
| `refill…` | Восполнить открытую область из скрытого запаса. |
| `replace…` | Заменить конкретный компонент другим. |
| `spend…` | Потратить ресурс и вернуть результат расхода. |
| `hire…` | Нанять помощника. |
| `validate…` | Проверить внешний ввод и вернуть/выбросить документированный результат ошибки. |
| `assert…` | Проверить внутренний инвариант; нарушение означает дефект программы. |
| `restore…` | Принять неизвестный сохранённый снимок, проверить и восстановить состояние. |
| `project…` | Построить безопасное для получателя представление без скрытых данных. |

Не использовать общие `handle…`, `process…`, `do…` и `manage…`, если можно назвать конкретное доменное действие.

## Форма идентификаторов

- Типы и события: `PascalCase`; функции, переменные и поля: `camelCase`; файлы: `kebab-case.ts`.
- Строковые дискриминаторы и имена команд: `snake_case`, например `perform_turn`.
- Доменные события называть в прошедшем времени: `GameStarted`, `RoundStarted`, `StartingLocationChosen`.
- Идентификатор одной сущности: `artistId`; массив идентификаторов: `artistIds`; словарь: `goalsByPlayerId`.
- Количество: `visitorCount`; индекс: `playerIndex`; булево значение: `isOpen`, `hasAssistant`, `canPurchase`.
- Коллекцию называть во множественном числе: `visitors`, не `visitorList`; суффикс `List` нужен только если структура списка важна для домена.
- Не использовать одно- и двухбуквенные сокращения вместо доменного смысла. Допустимы общеупотребимые технические сокращения `id`, `rng`, `api`, `dto`.
- Ошибки и константы ошибок должны называть нарушенный контракт, например `INVALID_INFLUENCE_SPEND_MESSAGE`.

## Добавление нового термина

1. Найти соответствующее правило и существующие идентификаторы.
2. Проверить, нельзя ли выразить смысл термином из этого словаря.
3. Если понятие новое и однозначное, выбрать одно английское имя и добавить строку в подходящий раздел.
4. Если выбор имени скрывает решение по механике или данным, остановиться и запросить решение пользователя.
5. При изменении существующего публичного имени отдельно определить область миграции и совместимость; не смешивать такую миграцию с несвязанным правилом.
