RULES_SPEC.md — источник истины для игровых правил.
DOMAIN_GLOSSARY.md — источник канонических английских имён предметной области.
Не угадывать данные со статусом needs_decision.
Перед добавлением публичных типов, полей и функций сверяться с DOMAIN_GLOSSARY.md; не вводить синонимы и не делать несвязанные массовые переименования.
Игровая логика живёт только в packages/game-engine.
Состояние игры неизменяемое: функции возвращают новое состояние.
Изменение правила включает тесты и обновление статуса спецификации.
После изменения движка запускать typecheck и test.
После изменения интерфейса запускать lint, test и build.
Не использовать оригинальные защищённые ассеты и оформление игры.

Общий протокол работы агента: `AGENT_HARNESS.md`. Читать его перед реализацией, ревью или аудитом. При первоначальной выдаче учебной задачи применять только быстрый выбор ниже; протокол не расширяет этот этап до аудита.

Если пользователь говорит «давай задачу», использовать `.agents/skills/galerist-task-cycle/SKILL.md`: ассистент выдаёт одну задачу, пользователь сначала присылает архитектурный эскиз и ручной прогон и переходит к реализации только после явного принятия; затем ассистент проверяет реализацию, пишет тесты и обновляет RULES_SPEC.md.
При первоначальной выдаче задачи использовать быстрый выбор: читать только выбранную запись правила, её трассировку, релевантные термины словаря и сигнатуры непосредственно связанных функций. Не запускать тесты, не читать полный diff, не обходить все незавершённые правила и не проводить глубокий аудит рабочего пути. Детальную проверку вызывающего пути выполнять после архитектурного эскиза пользователя.

npm run typecheck --workspace=@galerist/game-engine
npm run test --workspace=@galerist/game-engine

npm run lint --workspace=@galerist/web
npm run test --workspace=@galerist/web
npm run build --workspace=@galerist/web
