# Один цикл — одно проверяемое изменение

`RULES_SPEC.md` — источник истины. Читать только нужную запись, связанные ADR/DATA, код и тесты; искать по ID через `rg -n`. Не загружать весь реестр в контекст. Не угадывать `needs_decision` и непроверенные данные. Оставлять игровую логику в `packages/game-engine`, сохранять неизменяемость состояния.

## Когда пользователь просит задачу

1. Если указан ID, проверить его готовность. Иначе выбрать небольшой следующий блок с `spec: approved`, без блокирующих ADR или данных; сверить статус с кодом. Не выдавать одновременно несколько независимых правил.
2. Дать карточку задачи в ответе: ID и цель; точный контракт и границы; затрагиваемые модули; 2–4 наблюдаемых критерия приёмки, включая граничный случай и неизменяемость, где она применима; что прислать для проверки. Указать только нужные фрагменты спецификации, без её пересказа целиком.
3. Пользователь пишет код. Не менять реализацию и не выдавать готовый патч без его просьбы. На точечные вопросы отвечать по текущей задаче.

## Когда пользователь сообщает, что код готов

1. Посмотреть `git diff`, существующий код, релевантные тесты и запись правила. Не затирать изменения пользователя.
2. Проверить контракт, крайние случаи, типы и неизменяемость. Сначала назвать конкретные ошибки с местом и ожидаемым поведением. Если исправление требует изменения кода пользователя, предложить короткий следующий шаг; самому менять код только по его просьбе.
3. Когда реализация достаточно готова для проверки, написать или дополнить тесты на наблюдаемое поведение, включая ошибочный/граничный случай. Если тест выявил дефект, сохранить полезный падающий тест и сообщить о нём, не объявляя правило завершённым.
4. Запустить `npm run typecheck --workspace=@galerist/game-engine` и `npm run test --workspace=@galerist/game-engine`. После исправления пользователем повторить нужные проверки.
5. Обновить в `RULES_SPEC.md` только фактические `implementation`, `tests` и трассировку. `spec: approved` не выставлять без явного решения пользователя; `partial` сохранять, если не закрыт весь контракт. Сообщить результат и остаток работы по ID.

При изменении интерфейса дополнительно выполнять команды из `AGENTS.md`. Не создавать коммит без запроса.
